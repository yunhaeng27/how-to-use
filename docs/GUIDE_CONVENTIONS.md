# 가이드 문서 작성 컨벤션

이 저장소(`how-to-use`)에 새 가이드 문서를 추가하거나 기존 문서를 고칠 때 따라야 하는 규칙 모음. 새 문서는 아래 규칙과 어긋나면 안 됨.

이 문서는 사람이 읽는 규칙집인 동시에, AI 혹은 `guide-doc-style` 스킬이 문서를 교정할 때 참조하는 기준 문서임. 스킬은 이 문서의 내용을 그대로 따를 뿐 별도로 규칙을 복제해두지 않으므로, 여기만 고치면 스킬 동작도 함께 바뀜.

## 1. 디렉토리 구조

```
/NN_가이드명                      # 하나의 가이던스(메뉴얼)당 하나의 디렉토리
├── INDEX.md                     # (선택) 케이스/이슈 단위 Q&A 인덱스
├── NN_주제명.md                  # 본문 가이드. 00부터 순서대로 번호
├── assets/
│   └── images/                  # 가이드에서 참조하는 이미지
└── codes/
    └── NN_주제명/                # 문서 번호와 대응하는 예제 코드 폴더
```

- 최상위 디렉토리는 `NN_가이드명` 형태(두 자리 숫자 + 언더스코어 + 식별 가능한 이름). 예: `01_Langfuse`.
- 숫자 `99_`는 여러 가이드에 걸쳐 재사용되는 공용/부가 내용(예: `99_GenOS`)에 예약되어 있음. 특정 가이드 하나에 종속되지 않는 내용을 여기 정리하고, 각 가이드에서는 링크만 건다.
- 각 가이드 디렉토리 내부 문서도 `NN_주제명.md`로 번호를 매겨 읽는 순서를 명시. `00`은 해당 가이드의 개요/연동 방법 등 진입 문서.
- 이미지가 필요하면 `assets/images/`에 두고 문서에서는 상대경로로 참조.
- 예제 코드가 있으면 `codes/` 하위에 문서 번호와 같은 이름의 폴더를 만들어 대응시킨다(예: `01_langfuse_예제.md` ↔ `codes/01_rag_pipeline`).
- 새 가이드 최상위 디렉토리를 만들 땐 리포 루트 `README.md`의 규칙 문단도 함께 확인할 것.

## 2. 문서 구조 템플릿

```markdown
# {가이드명}

(선택) 주의 - 이 가이드가 다루지 않는 범위, 혼동하기 쉬운 인접 개념과의 경계를 한 문단으로 먼저 밝힌다.

## {핵심 개념 섹션}

개념 설명, 필요하면 예시.

*{이미지 캡션}*

![{이미지 캡션}](assets/images/xxx.png)

## {실제 사용법 섹션}

절차/코드/표.

관련 세부 내용은 [{다른 문서명}]({상대경로}.md)에서 확인.
```

- H1(`#`)은 문서당 하나, 가이드/문서 제목만 담는다. 마침표 없음.
- 본문 섹션 구분은 `##`만 쓴다. `###` 이하 소제목은 기존 문서에 없음 — 필요할 정도로 내용이 깊어지면 문서를 분리하는 걸 우선 고려.
- 제목 바로 다음, 첫 섹션 진입 전에 "이 가이드가 아닌 것"을 밝히는 주의 문단을 넣는 패턴이 반복됨(예: `00_langfuse_연동가이드.md`, `02_langfuse_평가.md`). 인접 개념과 헷갈릴 여지가 있는 주제라면 이 패턴을 유지.
- 문서 하나가 다른 문서의 예제/후속편이면 마지막에 다음 문서로 가는 링크를 남긴다.

## 3. 톤앤매너

- **개조식 반말체.** "~습니다/합니다" 존댓말이 아니라 "~함", "~됨", "~임", "~할 것", "~할 수 있음" 같은 개조식 종결을 쓴다. 설명서가 아니라 개발자가 스스로 남기는 기술 노트에 가까운 톤.
- 주어를 자주 생략하고 핵심 동작 위주로 짧게 쓴다. 마케팅 문구, 완곡 표현, 감탄사는 쓰지 않는다.
- 이야기하듯 배경을 설명하는 문단(예: "한 개발자가 에이전트를 개발한다고 해보자...")은 *이탤릭*으로 감싸서 본문 설명과 시각적으로 구분한다.
- 결론이 명확하지 않거나 제약이 있는 경우 이를 숨기지 않고 그대로 적는다(예: "불가능(X)", "-&gt; 이땐 어떻게 하느냐?"). 확실하지 않은 부분은 확실하지 않다고 쓴다.
- 코드/설정값/함수명/환경변수명은 항상 백틱(```)으로 감싼다.

## 4. 마크다운 스타일 세부 규칙

- 이미지 위에는 반드시 `*캡션*` 한 줄을 이탤릭으로 먼저 쓰고, 그다음 줄에 `![캡션](경로)`를 둔다.
- 표는 환경변수, 옵션 비교처럼 구조적으로 나열해야 하는 정보에만 쓴다. 산문으로 풀어쓸 수 있는 내용을 억지로 표로 만들지 않는다.
- 코드블록은 언어가 있으면 ````python` 처럼 언어 태그를 명시하고, 로그/의사코드성 스니펫만 태그 없이 `````를 쓴다.
- 다른 문서/코드 파일을 참조할 땐 항상 마크다운 링크로 연결한다. 파일명만 텍스트로 적지 않는다.
- 외부 링크(공식 문서, 대시보드 등)는 문맥 설명 없이 바로 `[설명(링크)](url)` 형태로 인라인.

## 5. 새 문서 체크리스트

- [ ] 올바른 `NN_가이드명` 디렉토리 아래에 있는가?
- [ ] 파일명이 `NN_주제명.md` 번호 규칙을 따르는가?
- [ ] H1 하나, 이후 `##` 섹션 구조인가?
- [ ] 인접 개념과 헷갈릴 수 있으면 도입부에 범위/경계 주의 문단이 있는가?
- [ ] 톤이 개조식 반말체로 일관되는가(존댓말/구어체 섞이지 않았는가)?
- [ ] 이미지에 이탤릭 캡션이 붙어 있는가?
- [ ] 코드/환경변수/함수명이 백틱 처리되어 있는가?
- [ ] 관련 문서·코드로의 상대 링크가 걸려 있는가?
- [ ] 이미지/코드 자산이 `assets/images`, `codes/`에 올바르게 위치하는가?
